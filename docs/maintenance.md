# 持续维护机制：不做一次性永不更新的教程

## 每月维护

- 从 Issue 中筛选失效官方链接、错误步骤、用户实际无法完成的操作。
- 检查 Google Search Central、Bing Webmaster Tools 最新相关文档；对发生变化的章节标注修订日期。
- 随机抽 3 章让完全新手跟做；留失败记录，不只展示成功截图。
- 运行 `python3 scripts/build.py && python3 scripts/site_audit.py _site && python3 -m unittest discover -s tests -v`。
- 移动端与桌面各做一次人工浏览；发布后再确认 Pages 不只是 Actions 显示成功。

## 任何内容 PR 必填

1. 原章节和操作问题。
2. 官方来源或可复现证据、核验日期。
3. 修改前后对照。
4. 对用户操作、验收和失败处理的影响。
5. 运行的测试与未完成的实测。

## 优先级

- 阻断：站点打不开、整站 noindex、错误规范网址、链接循环、内容与政策直接冲突。
- 高：教程不具备执行路径、实际工具按钮失效、把模拟案例写成事实。
- 中：示例不足、模板不够明确、可读性问题。
- 低：装饰、措辞或不影响完成任务的视觉微调。

## 版本标准

- V1：可部署、可阅读、可运行、主要事实核对、基础单元测试完成。
- V1.1：收集真实用户的跟做记录，修掉本地测试没发现的卡点。
- V2：实测案例库、更多 CMS 逐屏操作与官方政策更新；新增内容仍需证据。

避免“全网第一”之类不可证实排名宣称；以覆盖范围、可复现动作数和真实审核结果描述实际质量。
